# 外壳、视图与命令系统设计

> 本文定义用户看到的部分：窗口怎么分区、视图如何被插件贡献、命令如何统一派发、设置与工作区如何组织。
> 插件侧规则见 [plugin-system.md](plugin-system.md)；接口签名见 [api-contracts.md](api-contracts.md)。

## 1. 设计目标

- 像 VS Code 一样：左侧活动栏 + 侧边视图 + 中央标签页 + 底部面板 + 状态栏；
- 所有界面元素**由贡献点生成**，内置功能与插件走同一条注册路径；
- 所有按钮/菜单项最终都调用命令，不存在"绕过命令的私有槽函数"；
- 布局、活动会话、打开的视图可持久化并在重启后恢复。

## 2. 窗口解剖

```
┌ 标题栏 ────────────────────────────────────────────────────────────┐
│ 菜单栏：文件  编辑  会话  视图  插件  帮助                          │
├ 命令中心（搜索框，等价于命令面板入口） ─────────────────────────────┤
│ 活动栏 │ 侧边栏（视图容器）              │ 编辑区（标签页）          │
│  串口  │  ▸ 会话资源管理器               │  [COM3] [数据回放*]       │
│  插件  │  ▸ 插件                          │                          │
│  设置  │                                 │  会话控制台 / 插件编辑器   │
│        ├─────────────────────────────────┴──────────────────────────┤
│        │ 底部面板：输出 │ 命令终端 │ 日志 │ 问题                    │
├ 状态栏：活动会话 │ 速率 RX/TX │ 编码 │ 丢弃 │ 插件错误 │ 通知 ────────┤
└────────────────────────────────────────────────────────────────────┘
```

| 区域 | 承载 | 实现载体 |
|---|---|---|
| 菜单栏 | 全局命令 | `QMenuBar` + 菜单贡献 |
| 命令中心 | 命令/会话/文件的统一搜索入口 | 自定义 `QLineEdit`，复用命令面板模型 |
| 活动栏 | 视图容器切换（串口/插件/设置） | 垂直 `QToolBar`，由视图贡献生成 |
| 侧边栏 | 会话树、插件列表、设置大纲 | `QDockWidget`（左侧区域，标签化） |
| 编辑区 | 会话控制台、插件提供的编辑器视图 | 中央 `QTabWidget`（可关闭、可拖动、可拆分到后续） |
| 底部面板 | 输出、命令终端、日志、问题 | `QDockWidget`（底部区域，标签化） |
| 状态栏 | 会话状态、计数、通知、插件健康 | `QStatusBar` + 状态项贡献 |

选择 `QDockWidget` 的理由见 ADR-008：不引入第三方停靠库，视图抽象保证将来可以替换；`QDockWidget` 原生支持浮动/停靠/保存 `saveState()`。

## 3. 布局与持久化

- 布局由 `LayoutService` 统一管理：区域可见性、各区域当前标签、分割比例、窗口几何；
- 保存到工作区的 `.xcom/layout.json`，无工作区时保存到用户目录；
- 恢复原则：**视图 id 稳定**，找不到的视图静默跳过并记录日志，不阻塞启动；
- 关闭最后一个编辑标签不清空编辑区（保留空态页"没有打开的会话"）；
- 侧边栏与底部面板可隐藏，`视图` 菜单与命令均可切换。

## 4. 视图系统

### 4.1 视图位置

| 位置 | 容器 | 说明 |
|---|---|---|
| `activityBar` | 固定三个槽位 | 点击切换侧边栏容器；插件可替换槽位内容 |
| `sidebar` | `sessions` / `plugins` / `settings` | 侧边栏容器内以标签或折叠组展示 |
| `panel` | `output` / `terminal` / `logs` / `problems` | 底部面板容器 |
| `editor` | 编辑区标签页 | 每类视图可多实例（每个会话一个） |
| `statusBar` | 左/中/右三段 | 只放轻量文本/图标，不放复杂控件 |

### 4.2 视图描述与生命周期

| 字段 | 说明 |
|---|---|
| `id` | 全局唯一，如 `serial.console`、`serial.explorer` |
| `title` / `icon` | 标签页与活动栏显示 |
| `location` / `container` | 落点 |
| `order` | 同容器内排序 |
| `singleton` | 是否只允许一个实例 |
| `canClose` | 用户能否关闭（面板类通常否） |
| `retainWhenHidden` | 隐藏时是否保留实例（默认 false，节省内存） |
| `instanceKey` | 多实例视图的键（会话视图用 `SessionId`） |
| `factory` | 插件提供的工厂对象，首次显示时创建 |

生命周期：注册（`initialize`）→ 首次显示时创建 widget → 隐藏（可按配置销毁）→ 关闭/插件停用销毁。插件 `deactivate` 时，宿主关闭该插件全部视图并撤销贡献，无需插件自己记状态。

### 4.3 视图状态

每个视图通过 `IViewHost` 拿到自己的状态存储（JSON 片段），由宿主随布局一起保存，例如：滚动位置、HEX 开关、分栏比例、发送历史。视图不需要知道文件在哪。

## 5. 会话资源管理器（`serial.explorer`）

```
会话
 ├─ ● COM3  设备A        115200 8N1   RX 12.3 KB/s
 ├─ ○ COM5  传感器        9600 8N1    已关闭
 └─ ◐ replay:设备A-1021  回放中      1.0×
插件
 └─ 6 个已启用，1 个失败
```

- 每行显示：状态点、名称、端口、关键参数、实时速率/计数摘要；
- 右键菜单：打开控制台、重命名、复制参数、重新连接、关闭、导出配置；
- 双击：打开/聚焦该会话的控制台标签；
- 顶部工具条：新建会话、刷新端口、全部关闭；
- 空态：引导文案 + "新建会话"按钮（命令 `serial.session.open`）。

## 6. 会话控制台视图（`serial.console`）

每个会话默认打开一个控制台标签，布局：

```
┌ 工具条：名称 · 状态 · 端口/参数 · [HEX] [时间戳] [自动滚动] [暂停] [清空] [保存] ┐
│ 接收区（只读，等宽字体，可选中复制）                                              │
│ [12:00:01.234] 0D 0A 41 54 0D 0A ...                                              │
├───────────────────────────────────────────────────────────────────────────────────┤
│ 发送区（可编辑）                                                                   │
│ 工具条：[HEX 发送] [新行] [定时 1000ms] [历史▾] [发送]                             │
└───────────────────────────────────────────────────────────────────────────────────┘
```

| 行为 | 规则 |
|---|---|
| 渲染 | 由 `SessionController` 批量格式化，30 Hz 提交；不在 I/O 线程碰 UI |
| 大流量 | 超过阈值自动切换"采样显示"（每 N 块刷新一次），横幅提示，计数不丢 |
| 暂停 | 只停显示，引擎继续接收/录制/统计 |
| 自动滚动 | 用户向上滚动时自动暂停滚动，回到底部恢复；可手动锁定 |
| 选择 | 选中文本时暂停自动滚动，避免选区跳动 |
| 发送 | 支持文本/HEX/新行/定时；HEX 校验失败就地提示，不弹模态框 |
| 历史 | 最近 50 条发送记录，`↑/↓` 在发送区快速召回 |
| 关闭 | 关闭视图不关闭会话；会话仍可在资源管理器重新打开；可在设置中改为"关标签即断开会话" |

控制台视图本身放在 `ui-kit`（可被插件复用），会话绑定逻辑在 shell 的 `SessionController`。

## 7. 命令系统

### 7.1 命令描述

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一，`<域>.<对象>.<动作>`，如 `serial.session.open` |
| `title` | string | 命令面板显示文本，可含分类前缀 |
| `category` | string | 分组，如"会话"、"发送" |
| `icon` | string | 可选，用于菜单/工具栏 |
| `args` | CommandArg[] | 参数 schema，用于面板表单、CLI 解析、文档生成 |
| `enablement` | string | 上下文键表达式，不满足时菜单置灰、面板不可执行 |
| `background` | bool | 是否在任务线程池执行（默认主线程） |
| `singleton` | bool | 是否禁止并发执行同一个命令 |
| `hidden` | bool | 是否从命令面板隐藏（仍可用于键位/菜单） |
| `source` | string | 宿主自动填充：`core` 或插件 id |

### 7.2 参数类型

| 类型 | 说明 | 面板控件 | CLI 形式 |
|---|---|---|---|
| `string` | 任意文本 | 单行输入 | `--name value` |
| `int` / `float` | 数值，可带范围 | 数字输入 | `--baud 115200` |
| `bool` | 开关 | 复选框 | `--hex` / `--no-hex` |
| `enum` | 固定选项 | 下拉框 | `--parity even` |
| `session` | 会话引用（id/name/active） | 会话选择器 | `--session 设备A` |
| `path` / `file` | 文件或目录 | 文件选择器 | `--out ./log.txt` |
| `hex` | 十六进制字节串 | 单行输入 + 校验 | `--hex "AA 55"` |

参数支持 `required`、`default`、`description`、`choices`、`min/max`。命令面板据此自动生成输入表单，CLI 据此生成 `--help`，文档据此生成命令参考——**一处定义，四处复用**。

### 7.3 执行结果与进度

- 返回 `CommandResult { ok, message, data }`；`data` 为 `QVariantMap`，供脚本与 CLI 输出 JSON；
- 耗时命令通过 `ICommandProgress` 报告百分比与文案，支持 `cancel()`；
- 执行日志：`xcom.command` 记录命令 id、来源、耗时、结果码（不含敏感数据）。

### 7.4 来源与呈现

| 来源 | 失败呈现 | 成功呈现 |
|---|---|---|
| 菜单 / 工具栏 | 通知（可带"查看日志"） | 通常静默 |
| 命令面板 | 面板内提示条 | 关闭面板 |
| 内置终端 | 红色输出行 | 普通输出 |
| CLI | stderr + 退出码 | stdout（可选 JSON） |
| 脚本 | Promise reject | Promise resolve |
| 插件 API | 返回 `Result` | 返回值 |

## 8. 上下文键与 enablement

上下文键是"当前状态"的扁平字典，由宿主与插件维护：

| 键 | 类型 | 维护者 | 示例值 |
|---|---|---|---|
| `activeSessionId` | string | shell | `sess-8f3a1c` |
| `activeSessionState` | enum | shell | `open` / `closed` / `failed` |
| `sessionCount` | int | shell | `3` |
| `hasOpenSession` | bool | shell | `true` |
| `activeSessionRecording` | bool | shell | `false` |
| `editorFocused` | bool | shell | `true` |
| `terminalFocused` | bool | shell | `false` |
| `paletteVisible` | bool | shell | `false` |
| `workspaceTrusted` | bool | workspace | `true` |
| `plugin.<id>.<key>` | 任意 | 插件 | 自定义状态 |

表达式语法（刻意保持最小）：`key`、`!`、`&&`、`||`、`==`、`!=`、括号、单引号字符串。缺失键视为 `false`。注册时解析一次，运行时求值 O(1)。

## 9. 命令面板

- 触发：`Ctrl+Shift+P`、命令中心点击、菜单"查看 → 命令面板"；
- 输入 `>` 前缀进入命令模式（默认），`@` 跳转会话，`#` 搜索设置（后续）；
- 排序：前缀匹配 > 单词匹配 > 模糊匹配；同分按使用频率（frecency）与分类；
- 右侧显示当前键位（若有）；不满足 enablement 的命令置灰并显示原因提示；
- 必需参数在选中后就地展开表单，`Enter` 执行，`Esc` 返回列表；
- 最近使用 10 条置顶，可关闭；
- 未激活插件的命令也会出现（来自 manifest 元数据），执行时先触发激活。

## 10. 菜单、工具栏与状态栏

- 菜单路径由宿主固定：`menu/file`、`menu/session`、`menu/view`、`menu/plugin`、`menu/help`；上下文菜单：`context/sessionTab`、`context/sessionTree`、`context/console`、`context/palette`；
- 贡献项字段：`menu`、`group`、`order`、`command`、`when`、`label`（可覆盖命令标题）；
- 组间自动插入分隔线；同组按 `order` 升序；相同 order 按注册顺序；
- 菜单项永远是命令引用，不直接挂槽函数；
- 工具栏沿用同一份贡献数据（`menu/toolbar/<区域>`），避免两套配置；
- 状态栏分段：左（活动会话/端口）、中（RX/TX、速率、丢弃）、右（编码、插件错误、通知）；
- 状态项支持文本、图标、可点击（绑定命令）、进度条形态。

## 11. 键位

- 默认键位随代码发布；用户键位在 `keybindings.json` 覆盖；
- 规范化：统一小写、`ctrl+shift+p`，Windows 上 `ctrl`，macOS 映射 `cmd`（后续）；
- 冲突检测：同一 `when` 条件下同键位冲突 → 用户覆盖优先，其次插件，再内置；冲突列表在设置页展示；
- 组合键（chord，如 `ctrl+k ctrl+s`）在 v1 预留语法但不实现；
- 键位改动即时生效，无需重启。

默认键位：

| 键位 | 命令 | 说明 |
|---|---|---|
| `Ctrl+Shift+P` | `app.palette.show` | 命令面板 |
| `Ctrl+T` | `serial.session.open` | 新建会话（打开端口选择） |
| `Ctrl+W` | `serial.session.close` | 关闭当前会话（带确认，可关） |
| `Ctrl+Tab` | `serial.session.next` | 切换会话标签 |
| `Ctrl+Shift+E` | `view.sessions.focus` | 会话资源管理器 |
| `` Ctrl+` `` | `view.terminal.focus` | 命令终端 |
| `Ctrl+Enter` | `serial.data.send` | 发送 |
| `Ctrl+L` | `serial.console.clear` | 清空接收 |
| `Ctrl+Shift+H` | `serial.console.toggleHex` | 切换 HEX 显示 |
| `Ctrl+,` | `app.settings.open` | 设置 |
| `F1` | `app.palette.help` | 命令帮助 |

## 12. 设置

| 层 | 位置 | 作用 |
|---|---|---|
| 默认值 | 代码中的 `SettingSpec` | 出厂默认，不可改 |
| 用户 | `%APPDATA%/X-COM/settings.json` | 个人偏好，跨工作区 |
| 工作区 | `xcom.json` 的 `settings` 段 | 团队共享、项目相关 |
| 会话 | 会话描述符 | 单个会话的连接参数与显示偏好 |

规则：

- 键名强制命名空间：核心用 `core.*`，插件用 `<pluginId>.*`；
- 设置项声明时提供类型、默认值、范围、枚举、说明，宿主据此生成设置界面与 JSON schema；
- 非法值回退到上一层并记录警告，不阻塞启动；
- 变更立即生效（发布 `settings/changed`，带键路径），需要重建资源的由订阅方自行处理；
- 设置页支持搜索、按来源标记（用户/工作区/默认）、"重置为默认"；
- 现有 `QSettings` 配置在首次启动时自动迁移一次，迁移后写标记避免重复。

## 13. 工作区

一个工作区 = 一个目录，包含：

```
<workspace>/
├─ xcom.json          # 会话列表、设置、插件启用状态（建议纳入版本管理）
└─ .xcom/
   ├─ layout.json     # 窗口/停靠/标签布局（不建议提交）
   ├─ keybindings.json# 工作区键位（可选）
   └─ plugins/        # 工作区私有插件（默认禁用，需信任）
```

`xcom.json` 结构：

| 字段 | 说明 |
|---|---|
| `version` | 格式版本，用于迁移 |
| `sessions[]` | 名称、端口、参数、编码、是否自动重连、是否恢复 |
| `activeSession` | 启动时聚焦的会话名 |
| `views[]` | 默认打开的视图 id |
| `settings{}` | 工作区级设置覆盖 |
| `plugins.disabled[]` | 在该工作区禁用的插件 id |

信任：打开他人工作区时，`.xcom/plugins` 与脚本相关设置默认不生效，需"信任此工作区"；信任状态记录在用户目录，不写进工作区。

## 14. 通知、进度与输出

- 通知分级：info / warning / error，支持动作按钮（"重试"、"打开日志"），同类去重合并；
- 底部"输出"通道按来源分频道：`serial`、`plugin:<id>`、`commands`、`updates`；
- 长任务进度显示在状态栏（可取消），完成后成功静默/失败通知；
- 插件错误统一进"问题"面板，包含插件 id、时间、错误码、堆栈摘要。

## 15. 主题、图标与本地化

- 主题以 JSON 令牌描述（背景/前景/强调色/边框/等宽字体/圆角/间距），内置浅色、深色、跟随系统；
- 插件可贡献主题与图标；图标统一 SVG，使用 `currentColor` 以便随主题变色；
- 界面文本全部走 `tr()`，插件翻译随插件包分发（`translations/<lang>.qm`），语言切换需重启（v1）；
- 默认字体：界面用系统 UI 字体，数据区用等宽字体；字号可在设置中调整。

## 16. 可访问性与高 DPI

- 所有交互控件提供 accessibleName / description；
- 关键操作（打开/关闭/发送/清空）必须有等价命令，便于键盘与自动化；
- 支持 100%–200% 缩放；布局使用布局管理器，不写死像素；
- 不依赖颜色单独传达状态（状态点同时带形状/文本）。
